# AnswerBot

Telegram-бот с визуальным редактором потоков и системой статистики пользователей.

## Описание

AnswerBot — это полнофункциональный Telegram-бот с веб-интерфейсом для создания и управления диалоговыми потоками. Бот позволяет создавать интерактивные сценарии с кнопками, сообщениями и медиафайлами, а также отслеживать статистику взаимодействия пользователей.

## Основные возможности

- 🤖 **Telegram Bot** — обработка сообщений и callback'ов через aiogram
- 🎨 **Визуальный редактор** — создание потоков через веб-интерфейс
- 📊 **Статистика пользователей** — отслеживание действий и аналитика
- 🖼️ **Медиафайлы** — поддержка изображений в сообщениях
- 🔄 **Навигация** — кнопки "Назад" и "В начало"
- 📝 **Логирование** — автоматическое логирование всех действий пользователей

## Архитектура

Проект состоит из следующих компонентов:

- **Telegram Bot** (`bot/main.py`) — обработка сообщений и callback'ов через aiogram
- **Flask Admin Panel** (`admin/app.py`) — веб-интерфейс для управления ботом
- **База данных** — поддержка SQLite (по умолчанию) и PostgreSQL через Peewee ORM
- **Redis** (опционально) — очередь событий для асинхронного логирования действий пользователей
- **Event Worker** (`workers/event_worker.py`) — фоновый воркер для обработки событий из Redis

## Требования

- Python 3.8+
- PostgreSQL (опционально, по умолчанию используется SQLite)
- Redis (опционально, для логирования событий)

## Установка

### 1. Клонирование репозитория

```bash
git clone git@github.com:Pavuch0k/AnswerBot.git
cd AnswerBot
```

### 2. Создание виртуального окружения

```bash
python3 -m venv venv
source venv/bin/activate  # Linux/Mac
# или
venv\Scripts\activate  # Windows
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка переменных окружения

Скопируйте файл `.env.example` в `.env`:

```bash
cp .env.example .env
```

Отредактируйте `.env` и укажите необходимые параметры:

```env
# Обязательные параметры
TELEGRAM_BOT_TOKEN=your_telegram_bot_token_here
SECRET_KEY=your-secret-key-change-in-production
ADMIN_USERNAME=admin
ADMIN_PASSWORD=admin

# Опционально: PostgreSQL вместо SQLite
DATABASE_URL=postgresql://user:password@localhost:5432/answerbot

# Опционально: Redis для логирования
REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_DB=0
```

### 5. Инициализация базы данных

База данных создается автоматически при первом запуске. Если используете PostgreSQL, убедитесь, что база данных создана:

```bash
createdb answerbot  # PostgreSQL
```

## Запуск

### Локальная разработка

#### Вариант 1: Все компоненты отдельно

1. **Запуск админ-панели** (в одном терминале):
```bash
python wsgi.py
```

2. **Запуск Telegram бота** (в другом терминале):
```bash
python -m bot.main
```

3. **Запуск воркера событий** (если используется Redis, в третьем терминале):
```bash
python -m workers.event_worker
```

#### Вариант 2: Через Gunicorn (production-like)

1. **Запуск админ-панели через Gunicorn**:
```bash
gunicorn --bind 0.0.0.0:5000 --workers 2 wsgi:application
```

2. **Запуск бота** (в другом терминале):
```bash
python -m bot.main
```

3. **Запуск воркера** (если используется Redis):
```bash
python -m workers.event_worker
```

### Доступ к сервисам

После запуска:

- **Админ-панель**: http://localhost:5000
- **Логин**: используйте `ADMIN_USERNAME` и `ADMIN_PASSWORD` из `.env`

## Использование

### Создание потока

1. Откройте админ-панель в браузере
2. Войдите с учетными данными администратора
3. В визуальном редакторе создайте узлы:
   - **Стартовый узел** (`start`) — первое сообщение при `/start`
   - **Сообщения** (`message`) — текстовые сообщения с поддержкой HTML
   - **Кнопки** (`button`) — интерактивные кнопки для навигации
4. Свяжите узлы между собой, перетаскивая соединения
5. Загрузите изображения для сообщений (опционально)

### Статистика

В разделе "Статистика" доступны:

- Общая статистика пользователей
- График роста пользователей
- График активности
- Действия по типам
- Список пользователей с историей действий

## API для статистики

Все эндпоинты требуют аутентификации:

- `GET /stats` — страница статистики
- `GET /api/stats/overview` — общая статистика
- `GET /api/stats/users/growth?days=30` — график роста пользователей
- `GET /api/stats/actions/timeline?days=30` — график активности
- `GET /api/stats/actions/by-type?days=30` — действия по типам
- `GET /api/stats/users/list?page=1&per_page=20&search=...` — список пользователей
- `GET /api/stats/users/<user_id>/actions?page=1&per_page=50` — история действий пользователя

## Типы действий пользователей

Система автоматически логирует следующие действия:

- `start` — первый запуск бота (`/start`)
- `button_click` — нажатие на кнопку
- `back` — возврат назад
- `home` — переход в начало
- `message_view` — просмотр сообщения

## База данных

### Модели

- **Node** — узлы потока (start, message, button)
- **NodeConnection** — связи между узлами
- **MediaFile** — загруженные медиафайлы
- **User** — пользователи Telegram
- **UserAction** — действия пользователей

### Миграции

Таблицы создаются автоматически при первом запуске благодаря `safe=True` в `create_tables()`. При изменении моделей таблицы обновляются автоматически.

## Разработка

### Зависимости

Основные зависимости:

- `aiogram>=3.22.0` — Telegram Bot API
- `flask>=3.0.2` — веб-фреймворк
- `peewee>=3.17.1` — ORM
- `psycopg2-binary>=2.9.9` — PostgreSQL драйвер
- `redis>=5.0.1` — Redis клиент
- `gunicorn>=23.0.0` — WSGI сервер

### Логирование

Логи сохраняются в директории `logs/`:

- `bot.log` — логи бота
- `admin.log` — логи админ-панели
- `worker.log` — логи воркера
- `access.log` — логи доступа (Gunicorn)
- `error.log` — логи ошибок (Gunicorn)

## Безопасность

⚠️ **Важно для production:**

1. Измените `SECRET_KEY` на случайную строку
2. Используйте сильные пароли для `ADMIN_PASSWORD`
3. Не коммитьте файл `.env` в репозиторий
4. Используйте HTTPS для админ-панели
5. Настройте файрвол для ограничения доступа
